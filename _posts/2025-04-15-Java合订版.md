### 2. synchronized 和 ReentrantLock 的区别 (面试必考)

#### 1. 底层实现原理
- **synchronized (JVM 层面)**
  - **对象头 (Mark Word)**：锁状态存放在 Java 对象头的 Mark Word 中。
  - **Monitor 对象**：重量级锁依赖操作系统的 Mutex Lock，涉及用户态与内核态切换，开销大。
  - **锁升级**：JDK 1.6 后引入优化，过程为：**偏向锁 -> 轻量级锁 (CAS) -> 重量级锁**，只升不降。

- **ReentrantLock (JDK 层面)**
  - **AQS (AbstractQueuedSynchronizer)**：核心是一个 `volatile int state` (锁状态) 和一个 **CLH 双向队列** (等待线程)。
  - **CAS**：通过 `CompareAndSwap` 尝试修改 `state` 来获取锁。
  - **LockSupport**：利用 `park()` 和 `unpark()` 阻塞和唤醒线程。

#### 2. 核心区别对比
| 特性 | synchronized | ReentrantLock |
| :--- | :--- | :--- |
| **实现层面** | JVM 关键字 (C++ Monitor) | JDK API 类 (AQS) |
| **释放方式** | 自动释放 (代码块结束/异常) | **手动释放** (必须 try-finally unlock) |
| **公平性** | 非公平 | 默认非公平，可设为 **公平锁** |
| **等待可中断** | 不可中断 | 可中断 (`lockInterruptibly`) |
| **条件变量** | 单一 (`wait/notify`) | **多 Condition** (精准唤醒) |
| **锁升级** | 自动升级 (偏向->轻量->重量) | 无 (直接 CAS + 队列) |

#### 3. 什么是“可重入”？
- 两者都是**可重入锁**。
- **含义**：同一个线程可以多次获取同一把锁，不会自己把自己锁死。
- **原理**：内部维护一个计数器 (state/recursion count)，重入时 +1，释放时 -1，减到 0 才真正释放。

- BIO 是阻塞 IO，像村里邮差每户（连接）等信（读），每户一线程，高并发要万线程，内存爆，适合小网站。代码用 ServerSocket，read 卡线程。

## 什么是 ThreadLocal？

ThreadLocal 是 Java 提供的一种**线程本地变量**机制。它为每个使用该变量的线程提供一个独立的变量副本，使得每个线程都可以独立地改变自己的副本，而不会影响其他线程所对应的副本。

简单来说，ThreadLocal 实现了**线程间的数据隔离**，每个线程只能访问自己的本地变量。

### 底层实现原理

#### 核心数据结构

ThreadLocal 的底层实现依赖于 **ThreadLocalMap**，这是一个定制化的哈希表。

```java
// Thread 类中持有 ThreadLocalMap
ThreadLocal.ThreadLocalMap threadLocals = null;
```

每个 Thread 对象内部都有一个 `ThreadLocalMap` 类型的成员变量 `threadLocals`，用于存储该线程的所有 ThreadLocal 变量。

---

#### 🔥 ThreadLocalMap 在 JVM 中的存储位置

<aside>
💡

**核心结论：ThreadLocalMap 存储在 JVM 的堆内存（Heap）中，但逻辑上属于线程私有。**

</aside>

**详细分析：**

```
┌─────────────────────────────────────────────────────────┐
│                    JVM 堆内存 (Heap)                      │
│  ┌─────────────────┐    ┌─────────────────┐              │
│  │   Thread-1 对象  │    │   Thread-2 对象  │              │
│  │  ┌───────────┐  │    │  ┌───────────┐  │              │
│  │  │ThreadLocal│  │    │  │ThreadLocal│  │              │
│  │  │   Map     │  │    │  │   Map     │  │              │
│  │  │ (私有的)   │  │    │  │ (私有的)   │  │              │
│  │  └───────────┘  │    │  └───────────┘  │              │
│  └─────────────────┘    └─────────────────┘              │
└─────────────────────────────────────────────────────────┘
```

1. **物理存储**：Thread 对象是普通的 Java 对象，存储在堆内存中
2. **ThreadLocalMap 是 Thread 的成员变量**，随 Thread 对象一起存储在堆中
3. **逻辑上线程私有**：虽然在堆中，但只有对应的线程能通过 `Thread.currentThread()` 访问自己的 ThreadLocalMap

> ⚠️ **注意**：不要误以为 ThreadLocalMap 存储在栈内存或线程栈中。栈内存只存储基本类型和对象引用，对象实例本身都在堆中。
>

### 🔥 为什么 ThreadLocalMap 是线程安全的？

<aside>
🔒

**核心答案：ThreadLocalMap 天然线程安全，因为它根本不存在多线程访问的场景！**

</aside>

**线程安全的本质原因：**

| 对比项 | HashMap | ThreadLocalMap |
| --- | --- | --- |
| 所有者 | 可被多线程共享 | 每个线程独享一份 |
| 访问方式 | 直接引用 | 只能通过 Thread.currentThread() |
| 并发问题 | 存在竞争条件 | **不存在竞争** |
| 是否需要锁 | 需要（或用 ConcurrentHashMap） | **完全不需要** |

```java
public void set(T value) {
    Thread t = Thread.currentThread();  // ① 获取当前线程
    ThreadLocalMap map = getMap(t);      // ② 获取该线程私有的 Map
    if (map != null)
        map.set(this, value);            // ③ 只操作自己的 Map
    else
        createMap(t, value);
}
```

**关键点**：每次操作都是 `Thread.currentThread()` → 获取当前线程 → 操作当前线程的私有 Map。**线程 A 永远无法访问线程 B 的 ThreadLocalMap**，所以根本不需要加锁！

这是一种**空间换时间**的设计思想：通过让每个线程持有独立副本，从根本上消除了并发竞争。

### 🔥 Key 到底存的是什么？

<aside>
🔑

**Key 存储的是 ThreadLocal 对象实例本身的引用（弱引用），而不是线程 ID 或变量名！**

</aside>

### ThreadLocalMap 结构

```java
static class ThreadLocalMap {
    static class Entry extends WeakReference<ThreadLocal<?>> {
        Object value;
        Entry(ThreadLocal<?> k, Object v) {
            super(k);  // key 是 ThreadLocal 对象的弱引用
            value = v;
        }
    }
    private Entry[] table;  // Entry 数组
}
```

**常见误区澄清：**

| 误区 | 正确理解 |
| --- | --- |
| ❌ Key 是线程 ID | ✅ Key 是 ThreadLocal 对象本身 |
| ❌ Key 是变量名字符串 | ✅ Key 是 ThreadLocal 实例的引用 |
| ❌ 一个线程只能有一个 ThreadLocal | ✅ 一个线程可以有多个 ThreadLocal，每个作为独立的 Key |

**图解：**

```
Thread-1 的 ThreadLocalMap:
┌─────────────────────────────────────────────┐
│  Key (弱引用)          │     Value          │
├─────────────────────────────────────────────┤
│  ThreadLocal@0x001    │  "用户A的Session"   │
│  ThreadLocal@0x002    │  Connection@0x100  │
│  ThreadLocal@0x003    │  SimpleDateFormat  │
└─────────────────────────────────────────────┘
```

**为什么用 ThreadLocal 对象作为 Key？**

- 同一个线程可能使用多个 ThreadLocal 变量
- 通过 ThreadLocal 对象本身作为 Key，可以在同一个 Map 中存储多个不同的本地变量
- 每个 ThreadLocal 有唯一的 `threadLocalHashCode`，用于计算在数组中的位置

---

**关键点总结：**

- **Key**：ThreadLocal 对象本身（弱引用）
- **Value**：线程本地变量的值（强引用）
- 使用**开放地址法**（线性探测）解决哈希冲突

### 核心方法实现

- **set() 方法**

```java
public void set(T value) {
    Thread t = Thread.currentThread();
    ThreadLocalMap map = getMap(t);
    if (map != null)
        map.set(this, value);
    else
        createMap(t, value);
}
```

- **get() 方法**

```java
public T get() {
    Thread t = Thread.currentThread();
    ThreadLocalMap map = getMap(t);
    if (map != null) {
        Entry e = map.getEntry(this);
        if (e != null)
            return (T) e.value;
    }
    return setInitialValue();
}
```

## 内存泄漏问题

<aside>
⚠️

**为什么会内存泄漏？**

ThreadLocalMap 的 Key 是弱引用，当 ThreadLocal 对象被 GC 回收后，Key 变为 null，但 Value 仍是强引用，无法被回收，从而造成内存泄漏。

</aside>

**解决方案：** 使用完 ThreadLocal 后，务必调用 `remove()` 方法清理数据。

```java
try {
    threadLocal.set(value);
    // 业务逻辑
} finally {
    threadLocal.remove();  // 必须手动清理
}
```

## 常见应用场景

### 1. 数据库连接管理

```java
private static ThreadLocal<Connection> connectionHolder = 
    ThreadLocal.withInitial(() -> {
        return DriverManager.getConnection(url, user, password);
    });
```

每个线程独享一个数据库连接，避免连接被多线程共享导致的并发问题。

### 2. Session 管理

Web 应用中，将用户的 Session 信息存储在 ThreadLocal 中，方便在同一请求的不同处理方法中获取。

```java
public class SessionContext {
    private static ThreadLocal<User> currentUser = new ThreadLocal<>();
    
    public static void setUser(User user) {
        currentUser.set(user);
    }
    
    public static User getUser() {
        return currentUser.get();
    }
}
```

### 3. 日期格式化（SimpleDateFormat）

SimpleDateFormat 是线程不安全的，使用 ThreadLocal 为每个线程创建独立实例。

```java
private static ThreadLocal<SimpleDateFormat> dateFormat = 
    ThreadLocal.withInitial(() -> new SimpleDateFormat("yyyy-MM-dd"));
```

### 4. 事务管理

Spring 框架中使用 ThreadLocal 保存事务上下文，确保同一线程中的多个数据库操作在同一个事务中执行。

### 5. 链路追踪

在微服务架构中，使用 ThreadLocal 存储 TraceId，实现请求的全链路追踪。
